# DEPLOY.md · 部署手册（模板 · 配套工作手册 v7）

> 定位：两件事。①**环境在哪、怎么搭、怎么发、怎么退**——照着敲就能做完，不靠任何人的记忆（§A–§C）。②把「应用侧已经写完、但配置层配错时**静默失效**」的防线一次写清（§0–§5）。
> 什么时候写：阶段 0 定下部署环境时写 §A 初稿；第一次真实部署的任务边做边写 §B、§C，完成定义是「照本文件逐条执行成功」。在服务器上手工敲过的命令，当场记进来。
> 验收：开一个空上下文的会话（或只读子代理），只给它本文件，让它列出「发布一次」和「回滚一次」各要敲哪几条命令。列不全就是没写够。
> 这份文档在真实项目里的教训：应用层的每道防线（body 上限、超时、低权角色、密钥守卫）都有一个配置层的孪生开关——**配错时没有任何东西会报错**，只有事故会。
> 铁律：条条注出处（决策号 / 任务号）；迁移平台时旧文档整份保留为 `DEPLOY-{旧平台}.md`（部署文档同样只移不删）。
> 用法：把 {占位} 换成本项目实际值，删掉不适用的节。

## §0 · 上线前必做（「不做的后果」一栏是本表的精髓）

| 事项 | 谁做 | 不做的后果 |
|---|---|---|
| {反代 body 上限 / 写超时按应用侧参数配} | 人工 | {大文件上传静默 413/504，应用日志里看不到} |
| {`DATABASE_URL` 换成低权应用角色} | 人工 | {应用带 owner 权限跑，一次注入 = 全库} |
| {生产 `.env` 填齐 `{JWT_SECRET}` / `{ADMIN_PASSWORD}` / `{ENVIRONMENT}`} | 人工 | {密钥守卫若 fail-open，零凭据可签出管理员令牌} |
| {第三方服务 key 与域名/IP 白名单} | 人工 | {未配置=功能静默缺席；白名单错=生产不可用而开发一切正常} |
| {…持续追加} | | |

- {owner 连接串只给迁移用（独立 profile / 一次性容器）；应用运行用低权角色}

## §5 · 部署链路与回滚速查

- {构建在哪跑、镜像如何命名（内容寻址 sha tag）、部署由什么触发}
- **先迁移，后换代码**：迁移是增量的，旧代码容忍新 schema；反过来不成立。
- 回滚 = {把镜像引用（如 `.env.image`）指回上一个 sha tag 重新拉起}；保留最近 {N} 个镜像防盘满。
- **回滚演练与备份恢复必须实跑过一次**（镜像回退→健康→回正；最新备份恢复到独立库核对总数）——没演练过的回滚方案只是愿望。
- {每日备份 cron：目标位置 / 保留份数 / 恢复命令}
