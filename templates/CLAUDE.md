## TIER 1 · 硬规则（任何档位任务一律生效，违反即停）

1. **禁止提交密钥**：密钥/token 只放 `.env`（已 gitignore），仓库只提交 `.env.example` 占位。（为什么：进过 git 历史的密钥等于已泄露，事后删 commit 救不回来。）
2. **禁止直接 push main**：一律走分支 → PR → 合并。（为什么：main 是所有分支与 Agent 的共同基线，绕过 PR 就同时绕过了 CI 和评审两道闸。）
3. **合并前必须确认 CI 全绿**：All checks passed 才能合并，红绝不合并。有 `gh` CLI 时，AI 在建议"可以合并"之前必须先 `gh pr checks` 贴出 CI 状态；红就先修、不建议合并。（为什么：曾有项目 main 连续四个里程碑带红合并没人发现——本地总是绿的。）
4. **契约先行**：跨层接口（HTTP/WS/函数签名）先在 {shared 包/契约文件} 用 {zod/schema} 定稿 → 推导类型，两端各自校验；禁止在应用内重定义契约。（为什么：同一份契约写两处必然漂移，最后前后端各自为真。）
5. **禁止硬编码面向用户的文案**：一律走 i18n key（{zh/en} 双份）。
   > 按产品形态实例化：**明确的单语言产品可经用户拍板 + DECISIONS 留痕后整条挂起**（连 i18n 基础设施也不做）；挂起后禁止"顺手"零敲碎打上 key——半套 i18n 比没有更糟。硬规则要么生效、要么显式改掉，不能半死不活（被长期默默违反的硬规则会瓦解其他硬规则的权威）。
6. **数据库迁移不裸写 SQL**：一律经 {Prisma/迁移工具} 生成迁移，不删改既有迁移历史。（为什么：手写迁移绕过工具的状态追踪，环境之间会悄悄不一致；改历史会让已部署的环境无法升级。）
7. **危险命令先确认**：`rm -rf`、`DROP TABLE`、`git push --force`、`git reset --hard` 等破坏性命令，执行前必须停下向我确认（常规 `node_modules`/`dist` 清理除外）。（为什么：不可逆。优先用 permissions 硬拦截，本条只是兜底。）
8. **不随意加新依赖**：引入任何新依赖前说明理由并等我确认。（为什么：每个依赖都是长期的供应链风险与维护负担。）
9. **涉敏里程碑收口必须过安全审计**：涉及鉴权/支付/PII/文件上传/用户输入入库的里程碑，合并前跑一次 A5 安全审计（子代理或新会话跑，不在实现会话里自审），高危清零才能合并。CI 必含 secret 扫描 + 依赖审计（机制配置见手册附录 A7，属 M0 的 DoD）。

## TIER 2 · 工作方式

- **一个任务一个 commit**（PLAN.md 里的一个 T-编号）：四命令绿 → commit + 勾选 + Evidence 回填 → 输出进度块（`prog`）。想连做多个任务用 `/kof a` 自动循环（见下条）；状态永远落在 PLAN 与 git 里而不是会话记忆里，所以任何时刻 /clear 都能用 `/kof c` 无损续跑。
- **多 Agent 任务必须先 claim**：PLAN 任务状态改为 claimed / in_progress，填 Owner、Worktree、Writable Scope 后再动手。
- **只写可写范围**：Writable Scope 之外的文件不要顺手改；必须越界时停下说明。
- **commit 粒度**：代码改动 + PLAN 勾选本任务 + DECISIONS 追加（如有），同一个 commit。
- **执行节奏**：默认做完一个任务停下，我说"继续"再做；我用 `/kof a` 开自动循环时连做不等发话，但命中停止条件必须停——队列做完（等我合并，**永不自动合并 PR**）、CI 红连修两次不过、四命令不绿、需要我拍板或 Evidence 写了 `待拍板：`、撞 TIER 1 拦截项或要越 Writable Scope、上游欠账阻塞、命门任务做完{默认停；若本项目已拍板"命门照做不停"，写明决策号 D××}、下一个是收口任务（走 `close`）、上下文明显变大。loop 省的是发话，不是门禁。
- **卡在方案上可以找另一个模型讨论**（规程见 `kof`）：回复先实测复核再采信；"某模型说"不写进 Evidence 当依据，也不构成我的授权。{若本项目限制代码外发第三方模型，在此写明}
- **如实写 Evidence**：需要我知道的事单独起一行——`待拍板：…`（会让执行停下）/ `偏差：…`（不停，挂到收口裁决）。我只能通过进度块看到项目，不写的偏差就是收口时的意外。
- **检查红了先查根因**；同一问题连修 3 次不过就停下报告。任何时候不许靠删除/跳过/弱化测试与断言、或删掉报错的功能来让检查变绿。
- **双轨并行**：切片内契约冻结后，前后端两泳道可并行；后端先行上限 = 本切片 + 下一切片【设计无关】任务，绝不预做未来旅程的 API；里程碑完成 = 旅程走通，收口前先"按旅程联调"。
- **只做本任务**：不顺手改无关模块、不提前做下一个任务。
- **改结构化文档（PLAN/PRD/DECISIONS）只增量编辑**：逐段改、禁止整文件重生成；归档只"移动"不"删除"；改完 `git diff` 核对 checkbox 数量与结构未被破坏。
- **文档规模化节拍**：PLAN 只留当前里程碑（收口时归档进 PLAN-ARCHIVE）；DECISIONS 满一个 Phase 分卷归档（活跃文件只留索引+当前 Phase）；子系统参考文档（{DOMAIN}.md）在收口时同步。
- **前端视觉的单一真相是 DESIGN.md**：改样式前先读它；禁止在组件里硬编码颜色/间距/字号。

## 易错点（踩过的坑，持续追加）

- **切新里程碑分支前**：`git log origin/main` 确认上一里程碑**全部** commit 已进 main——不是看到一次 Merge 就以为完整；里程碑首次合并后追加的 commit 必须再开 PR 合并。同时 `gh run list --branch main` 确认 main 自身 CI 为 success。
- **四命令全绿 ≠ 布局对**：测试/lint/typecheck 抓不到裁切、横向溢出、错位。凡渲染/改动了界面的任务，commit 前在 preview 跑布局断言，**两条必须一起跑，缺一条就是假绿**：
  - `scrollWidth - clientWidth === 0` —— **它在祖先有 `overflow:hidden` 时恒为 0**，而那正是"元素被裁掉但页面不滚"的形态：它测不出自己；
  - 最右元素 `getBoundingClientRect().right` ≤ 容器右缘 —— 这条才是真的。
  在**项目声明的基准视口**重跑（移动优先 375px / 桌面优先按最小支持宽度，替换须记 DECISIONS）；**登录成真实角色、带最宽真实数据量**——按角色渲染的 UI 没登录时量到的是另一个界面。
- **本地绿 ≠ CI 绿**：本地 dist/.env 残留会掩盖问题。改了构建/依赖/生成步骤时，先本地模拟 CI（清 dist/缓存 + 无 .env，按 CI 步骤顺序跑）验证，再推。
- **命令接管道会吞退出码**：`{lint 命令} 2>&1 | tail` 让 `&&` 链看到 tail 的 0，lint 红着也能提交推送。要么不接管道，要么 `set -o pipefail`。
- **`gh run rerun` 复用原 run 的 workflow 快照**：修了 ci.yml 之后 rerun 旧 run 等于原地踩同一个坑——必须触发新 run（`gh pr update-branch` / 空提交）。
- **CI job 秒级失败（<60s）先想磁盘/runner/基础设施，别急着当代码问题重跑**：这类报错常在 check-run 注解里而不在步骤日志（`gh api .../check-runs/{job_id}/annotations`）。
- **接口隔离变化**：会被替换实现的能力（占位 → 真实现），签名按**未来实现的形态**定（DB/网络 → 异步 Promise），换实现时只改内部、上层零改动。
- **延后/预留决策必须留痕**：当场记 DECISIONS（延后什么、归属哪个里程碑、当前怎么占位、为什么），相关文档处加"见 D××"交叉引用。
- **上层目录的 CLAUDE.md 会被一并加载**：Claude Code 向上递归读取父目录的 CLAUDE.md，父目录遗留的旧宪法/模板会污染并顶撞本文件。开项目前检查仓库之上的目录，删掉或对齐过期的 CLAUDE.md。
- {项目自己踩的坑，持续追加：现象 → 根因 → 规避动作（出处 M__-T__ / D__）。同类坑第二次出现 → 升格为机制（permissions / hook / CI 闸门）；第三次 → 改代码结构（手册护栏 12）}
