# kof · 标准开工流程

> 本 skill 是**手册纪律的执行入口**：它不替代 PRD / PLAN / DECISIONS / CLAUDE.md，冲突时一律以仓库文档为准（AGENTS.md > CLAUDE.md > 本 skill）。
> 安装：整个目录**原样**复制到项目的 `.claude/skills/kof/`（Codex：`.agents/skills/kof/`），不需要改任何内容；Claude Code 项目再把下方【hook 安装】那几行加进 `.claude/settings.json`，让 clear / 压缩之后自动接上重载。
> **本 skill 不放项目状态**（手册规则：skill 只放稳定方法）。项目的具体事实从项目文档读：根命令与业务红线 → `ENGINEERING.md`；命门清单、涉敏点、本机环境、常设悬案、踩过的坑 → `CLAUDE.md`；基准视口与模式豁免 → `AGENTS.md`「运行模式声明」。这样 skill 可以随手册升级直接覆盖。
> 配套 skill：`prog`（进度块）、`close`（里程碑收口验收门）。

## 模式判定（看参数第一个词）

| 参数 | 模式 | 流程 |
|---|---|---|
| （无参数） | **一 · 续接**（最高频，故为默认） | 只走【续接流程】 |
| `c`（记法：**c**lear 周期；或 `reload`/`重载`） | **二 · 清场与重载** | 上下文里有活 → 【清场阶段】清点 → 落盘 → clear；上下文空（刚 clear / 新会话）→ 【重载阶段】定位 → 读 → 自查 → 补漏 → 执行 |
| 任务号（一个或多个，或区间） | **三 · 指定** | 跳过定位，走完整流程的读 → 自查 → 执行；**只做点到的任务** |
| `a`（记法：**a**uto；可带起点或区间：`/kof a M3-T2..T4`） | **四 · 自动循环** | 从最早未完成任务（或指定起点）开始连做，不等用户逐个发话；命中【停止条件】即停 |

## 模式一 · 续接（无参数默认，同会话继续，轻量）

前提：本会话上下文里**已有进行中的任务**（规则和任务描述都读过了）。此模式**不重读**文档，只做两件事：

```
git status -sb && git log --oneline -3
```

1. 用上述命令确认落点（改到哪了、有没有未提交的东西），与上下文记忆对齐；
2. 直接从中断处继续执行，纪律沿用上下文里已载入的那套。

若上下文里**找不到进行中的任务**（比如 /clear 过、或换了会话误用此模式）→ 说明情况并改走模式二的重载阶段，不硬猜。

## 模式二 · 清场与重载（`/kof c`）

> 一条命令走完“清点 → 落盘 → clear → 重载 → 补漏”。**判阶段看上下文：有进行中的活 → 清场阶段；空的（刚 clear / 新会话）→ 重载阶段。**
> 为什么要清场：会话里最容易丢的不是代码（在盘上），是**只在对话里的东西**——用户的口头约定（“不动 X”“不装 Y”“授权 Z”）、做到哪一步、试过什么没成、在途的 PR / 后台任务。上下文被压缩时它们无声消失，事后谁也想不起来漏了什么。

### 什么时候提清场（不等用户发现丢了才说）

命中任一 → 当前步骤做完就说一句「建议清场：`/kof c`」：

- 上下文里出现过**压缩摘要**——信息已经丢了，别再靠它续；
- 用户说“我说过了 / 之前讲过”——丢失已发生：先把那条落盘，再提清场；
- 刚做完【重型】任务；本会话已做 ≥ 3 个任务；同一问题连修 ≥ 3 次的长调试；跨过了一次里程碑收口；
- **你读不到自己的上下文占用**：拿不准就按偏大处理。

### 清场阶段（上下文里有活）

1. **清点**——逐类问“在我脑子里、不在盘上的有什么”，落到对应位置：

| 类 | 查什么 | 落到哪 |
|---|---|---|
| 代码 | `git status -sb`、`git stash list`、`git worktree list`、未推送提交 | WIP 提交到任务分支（`M{x}-T{y}: WIP · 交接`），**不用 stash**——新会话看不见它 |
| 任务状态 | PLAN 勾选 / Evidence 是否反映已做的；做到哪一步、试过什么没成 | 该任务 Evidence 加一段 `交接：`（交接包字段见 `AGENTS.md`） |
| 会话里的口头约定 | 用户说过、任何文件里都没有的：不动 X / 不装 Y / 授权 Z / 拍板 W | 决策 → DECISIONS；常设约束 → `CLAUDE.md`「常设悬案」；只关本任务 → Evidence |
| 在途 | 开着的 PR、跑着的 CI / 后台任务、等用户回答的问题 | 交接包「在途」 |
| 环境事实与踩坑 | 端口、代理、偶发失败的测试、目录结构的坑 | `CLAUDE.md`「本机环境」/「易错点」 |
| 临时文件 | scratchpad 里有用的草稿、规格 | 进仓库，或交接包记路径 |
| 标记 | 该写没写的 `待拍板：` / `偏差：` | Evidence |

2. **落盘并提交**：WIP 提交默认做（可回滚点；最终提交跟在后面，不改写已推送的历史）；PLAN / DECISIONS / CLAUDE.md 只增量编辑。
3. **输出清点单**（一屏：落了什么、到哪；没落、需要用户确认的单列），末尾问一句：「会话里还有我没列到的约定吗？没有就说“清”。」
4. **clear**：Claude Code 桌面版 → 用户说“清”后调 `clear_session`（延迟工具，先 `ToolSearch` `select:mcp__ccd_session_mgmt__clear_session`；`session_id: "self"`，本轮结束时清）；CLI → 请用户输入 `/clear`；Codex → `/new`。清之前把重载方式说清：装了 hook 的项目，清完后用户的下一条消息（随便一句）自动进重载阶段；没装的输入 `/kof c`。

### 重载阶段（上下文空）

1. **先找交接**：装了 hook 时，落点、第一个未完成任务、最新 `交接：` 行、上一段会话里用户说过的话已经在上下文里（脚本只读，见【hook 安装】）；没装就自己跑 `python3 <kof 目录>/session-start.py --source clear --previous`。有交接包 → 从交接包续，不从“第一个 `- [ ]`”重新猜。
2. **定位任务**（没有交接包时）：

```
grep -n "^- \[ \]" PLAN.md | head -3
```

PLAN.md 按里程碑时间序排列，**第一个 `- [ ]` 就是最早的未完成任务**——接手它（命中多个只做第一个）。

**零命中**（当前里程碑全勾完）→ 不擅自开新里程碑，进入**立项流程**：
1. 先确认上一里程碑已收口（`git log origin/main` 全部 commit 已进 main、CHANGELOG 已记、任务已归档 PLAN-ARCHIVE）；没收口 → 提示走 `close`；
2. 看 PLAN.md 里**下一个未开的占位里程碑**（建议在 PLAN 尾部预放占位行当路线图——自动循环在里程碑边界就不迷路）；没有占位则向用户要方向；
3. 按手册 JIT 在 `PRD.md §11` 补该里程碑的字段级规格 + 记 DECISIONS；
4. 拆任务写进 PLAN.md（**增量编辑**）；
5. **等用户确认后再实现**，不许跳过确认直接写代码。

3. 走【完整流程】第一步（读）、第二步（自查）。
4. **补漏检查**——这一步不省：
   - 交接包 vs 现实：`git status` / PLAN / `gh pr list` 里有、交接包没提的（多出来的改动、开着的 PR、stash）→ 列出来；
   - 上一段会话用户说过的话逐条对照：已落盘的略过，没落盘的列出来（该进 DECISIONS / 悬案 / Evidence 的当场补）；
   - 问用户一句：「以上是我找回来的，会话里还说过别的吗？」——**用户是唯一记得口头指令的人**。
5. 报一句「接手 M__-T__ · <任务名>，从 <交接包里的下一步> 续」再动手——找错任务闷头干到一半，比多说一句话贵得多。

### 上下文被压缩（不是 clear）

hook 的 `compact` 触发点会注入同样的落点与用户原话。**把压缩摘要当线索，不当事实**：按重载阶段 3–4 重读 PLAN / DECISIONS 并补漏，再继续。

### hook 安装（Claude Code；让 clear / 压缩 → 重载自动接上）

项目 `.claude/settings.json`（与 `permissions` 并列；SessionStart 的 matcher 是精确串，不是正则，所以写两条）：

```json
"hooks": {
  "SessionStart": [
    {"matcher": "clear",   "hooks": [{"type": "command", "command": "python3 \"${CLAUDE_PROJECT_DIR}/.claude/skills/kof/session-start.py\""}]},
    {"matcher": "compact", "hooks": [{"type": "command", "command": "python3 \"${CLAUDE_PROJECT_DIR}/.claude/skills/kof/session-start.py\""}]}
  ]
}
```

- 只在 `/clear` 后与上下文压缩后运行（官方文档：SessionStart 的 `clear` / `compact` 触发点，纯文本输出进上下文；命令经 `sh -c` 在项目目录执行，`CLAUDE_PROJECT_DIR` 由 Claude Code 导出）；`startup` / `resume` 静默。
- 只读，不写任何文件；会话记录在本机 `~/.claude/projects/<项目>/*.jsonl`，只取**用户自己的消息**（不含工具输出、子代理、AI 回复），最近 30 条、各截 200 字（`-n` / `--width` 可调）。
- 装好后第一次 `/clear` 就是验收：下一条消息前，上下文里应出现以「kof · 上下文已清」开头的一段。Codex 没有等价机制：清完手动 `/kof c`。

## 模式三 · 指定任务（单个 / 批量 / 区间）

- 单个：`/kof M3-T2`
- 批量：`/kof M3-T2 M3-T3 M3-T5`（空格分隔，按给出顺序执行）
- 区间：`/kof M3-T2..T4`（展开为 T2、T3、T4）

批量规则：
1. 批量＝用户**明确授权**在一个会话里顺序连做，但**逐任务独立收尾**——每个任务各自四命令绿、各自 commit、各自输出进度块，做完一个再开下一个，绝不合并提交。
2. 队列里撞到 PLAN 标了**【单独+确认】/ 命门**的任务 → 做完它后**停下等用户确认**再继续队列（批量授权不覆盖命门确认门）。项目命门清单见 `CLAUDE.md`。
3. 某个任务失败/被阻塞 → 停下报告，**不跳过它继续后面的**（后序任务往往依赖前序）。
4. 开工前把整个队列报告一遍：「本会话依序执行：M__-T__、M__-T__ …」。队列做完即停，不自动接队列之外的任务。

然后走下方【完整流程】。

## 完整流程（模式二 / 三 / 四共用）

### 第一步 · 读（不读完不许写代码）

1. `AGENTS.md` + `CLAUDE.md` + `ENGINEERING.md` —— 协作入口、TIER1 硬规则、根命令与业务红线。（Claude Code 里它们已随 `CLAUDE.md` 的 import 自动载入，本会话没 /clear 过就不必重读。）
2. `PLAN.md` —— **当前里程碑整段**：里程碑头（目标 / DoD / 原则 / 范围边界）+ 目标任务描述（即验收标准）+ 已完成任务的 Evidence 与踩坑留痕（前序设计决定都在里面）。
3. `DECISIONS.md` —— 索引表 + 最新 2–3 条（当前 D 编号见索引表尾部）；**不读 `DECISIONS-ARCHIVE.md`**，除非任务点名某条已归档决策。
4. 按需：涉及契约/字段 → `PRD.md §11` 对应里程碑段；涉及前端视觉 → `DESIGN.md`。
5. （启用了 `.vibe/` 的项目）`.vibe/project.json` 与当前 `.vibe/tasks/{task-id}.json`；与 PLAN 冲突时停下交 Integration Owner 裁决。

### 第二步 · 自查时效状态（用命令，不用记忆）

```
git status -sb                        # 当前分支、是否干净、与远端差距
git log --oneline -5                  # 最近提交（前序任务的落点）
gh pr list                            # 开放 PR
gh run list --branch main --limit 1   # main CI 状态（红着不准起跑）
```

外加 `CLAUDE.md`「本机环境与常设悬案」里列的依赖服务健康检查命令（如有）。

- **多 Agent / 并发会话**：动手前先 claim（PLAN 任务的 状态 / Owner / Worktree / Writable Scope），确认号段已分好（里程碑号、决策号 D__）；共用本地服务时错峰跑重负载测试。
- **本机环境常设事实、常设悬案**：读 `CLAUDE.md`「本机环境与常设悬案」。悬案除非任务明说，不许顺手碰。
- **受保护文件**（改动须【单独+确认】并走 Integration Gate）：契约/schema、迁移历史、锁文件、CI 配置、生成文件、设计 token。

### 第三步 · 执行纪律

1. **recon 到 file:line 再动手**。计划前提被 recon 推翻 → 改计划并在任务 Evidence 里留痕，不硬做。
2. **契约先行**：跨层接口先在契约单一真相处定稿 → 生成/推导两端类型 → 应用层只消费，禁止两处定义。契约冻结后的破坏性变更必须新开 DECISIONS 条目。
3. **数据迁移**：一律经工具生成、不裸写 SQL、不删改既有迁移历史；autogenerate 的产物**必须人工审**（误删系统表 / 重复索引 / 类型残留是常见坑）；跑 upgrade → downgrade → upgrade 全循环再算过。
4. **动 UI**：改界面的任务 commit 前跑**布局程序化断言，两条一起跑**（`scrollWidth - clientWidth === 0` 单跑是假绿；必须同时验最右元素 `getBoundingClientRect().right` ≤ 容器右缘），登录成真实角色、带最宽真实数据，在项目声明的基准视口重跑（见 `AGENTS.md` 运行模式声明；默认 375px）；click 后等渲染再读 DOM；四命令全绿 ≠ 布局对。
5. **验结果，不验调用**：写操作 / 注册 / 渲染类改动，断言可观察结果（数据真的落了、元素真的画了），不以"函数没抛错"为完成依据；空 catch 块是禁止项。
6. **接口隔离变化**：会被替换实现的能力，签名按**未来形态**定（异步、可空），换实现时上层零改动。
7. **文案与业务红线**：面向用户文案走 i18n key（除非模式声明已挂起该条）；业务红线见 `ENGINEERING.md`「数据与运行约定」。
8. **批量改代码用逐条断言存在的精确替换**，不用盲正则 sed。
9. **检查红了先查根因再修**；同一问题连修 3 次不过就停下报告、转而质疑方案。**任何时候都不许靠删除 / 跳过 / 弱化测试与断言、或删掉报错的功能来让检查变绿。**

### 第四步 · 任务收尾（每任务）

`ENGINEERING.md` 的四根命令从仓库根逐条跑绿（**不接管道**——`| tail` 会吞掉退出码）→ 代码改动 + PLAN.md 勾选 + **Evidence 回填**（≤ 800 字：做了什么、关键取舍为什么、实测数字、踩坑留痕；逐条输出与日志放 PR 描述）+ DECISIONS 追加（如有），**同一个 commit** → message 用 `M{x}-T{y}: 描述` 并说清"为什么"。

- **需要用户知道的事，在 Evidence 里单独起一行**：`待拍板：…`（需要用户决定——会让自动循环停下）/ `偏差：…`（与完成定义不一致、没测到的范围、临时绕过——不停，挂到收口裁决）。如实写；不写的偏差就是收口时的意外。**标记行只写一句话**（是什么 + 影响到哪），细节留在 Evidence 正文。
- PLAN / PRD / DECISIONS **只增量编辑，永不重生成**；改完 `git diff` 核对 checkbox 数量与结构未被破坏。
- 分支命名 `agent/{agent-id}/{task-id}-{slug}`；**禁止直推 main**（纯文档改动同样走分支 → PR）。
- 禁止提交密钥、`.env`、生成物。
- 装了 `map` skill 的项目：静默刷新项目地图（`python3 <map 目录>/map.py --quiet`，地图里配了「发布：」就加 `--publish`），成功时没有输出，不贴进对话。
- **最后输出进度块**：按 `prog` skill 跑脚本、原样贴出。这是每个任务收尾的固定最后一步，不省略。

### 第五步 · 里程碑收口（仅收口任务）

走 **`close` skill**，不在这里凭记忆做。收口是步骤最多、最容易漏的一道门。

## 模式四 · 自动循环（`/kof a`）

> 回填自真实项目（TideAnywhere，M1 起用到 M11）：用户不想"每个任务都打一次字"，又不能放弃门禁。**loop 省的是发话，不是门禁。**

`/kof a`＝从最早未完成任务开始连做；`/kof a M3-T2`／`/kof a M3-T2..T4`＝指定起点或区间后连做。
驱动（Claude Code）：每完成一轮用 `ScheduleWakeup` 排下一轮（`prompt` 原样回传 `/kof a`）；命中停止条件时**必须显式 `ScheduleWakeup stop:true`**，不留悬空唤醒。没有该工具的环境（Codex 等）：同一会话内直接接着做下一轮，或用工具自带的长程机制（Codex `/goal`）。

### loop 不豁免任何硬规则

TIER 1 全部照旧：不直推 main、不自审 A5、危险命令先确认、不擅自加依赖、契约与迁移照样人工审、**永不自动合并 PR**。

### 每轮做什么

1. `git status -sb` ＋ `grep -n "^- \[ \]" PLAN.md | head -3` 定位本轮任务。上下文仍在则不重读规则；新会话或上下文已丢失 → 先走模式二重载阶段（读规则 + 补漏）。
2. 报一句「loop 第 N 轮：接手 M__-T__ · <任务名>」再动手。
3. 按【完整流程】第三步执行 → 第四步收尾（四命令绿 + 代码 / PLAN 勾选 / Evidence / DECISIONS 同一 commit + **进度块**）。
4. 首个任务完成时建分支 → commit → push → 开 PR；后续任务 push 进同一分支同一 PR，**每次 push 后 `gh pr checks --watch`**，CI 红即按停止条件处理。分支名用区间，如 `agent/claude/m3-t2..t4-loop`。
5. 排下一轮，或按停止条件停。

**命门任务在 loop 里的默认处置：做完停下等人工核验**（手册护栏 6）。项目可以经用户拍板 + DECISIONS 留痕改为"命门照做不停"（TideAnywhere 先例）——代价写清楚：合并前必须按手册护栏 7 对最危险的 1–2 个命门做针对性自审（只读、证据 file:line、扫竞态 / 降级 / 信任边界）。无论哪种，四命令绿、Evidence 回填、DECISIONS 追加一项都不能省。

### 停止条件（命中任一：立即停 + 取消后续唤醒 + 一段汇总 + 进度块）

| 条件 | 处置 |
|---|---|
| 队列做完 / 当前里程碑无未完成任务 | watch CI 绿后**停下等用户合并**——loop 永不自动合并 PR |
| CI 红 | 当轮修；同一处连修两次仍红 → 停下报告 |
| 四命令任一不绿且非当轮可修 | 停下报告，不带病进下一轮 |
| 需要用户拍板（范围、取舍、数值、许可、命门方案分歧）；或本轮 Evidence 写了 `待拍板：` | 停下问，不猜 |
| 撞上 TIER 1 拦截项（合并、加依赖、危险命令、直推 main）；要越 Writable Scope 或动受保护文件 | 停下要授权 |
| 上游欠账阻塞（EXT-* 类）或跨仓库依赖未到位 | 停下报告，不催不接手 |
| 命门任务做完（默认；项目已拍板"照做不停"的除外） | 停下等人工核验 |
| 下一个是里程碑收口任务 | 单独停下，确认后走 `close`（A5 须子代理跑、禁自审） |
| 命中模式二「什么时候提清场」任一信号（压缩摘要出现、用户说“我说过了”、刚做完重型任务、本会话 ≥ 3 个任务、连修 ≥ 3 次） | 停下，走模式二清场阶段（清点 → 落盘 → clear）；重载后 `/kof a` 续跑 |

`偏差：` **不**触发停（它挂在进度块里到收口裁决）；但偏差若意味着完成定义没达成，那是 `待拍板：`，要停。
零命中（里程碑全勾）时**不擅自开新里程碑**——照模式二的立项五步走，第 5 步等用户确认，loop 在此停。

## 遇到需要方案的问题 → 找另一个模型讨论

> 同样回填自 TideAnywhere。异构模型盲区不同；但它是**顾问**，不是裁判，更不是授权来源。

**触发**（满足其一）：① 两种以上做法各有代价、证据不足以自决；② recon 推翻了原计划前提；③ 同一问题连试两次仍失败；④ 命门任务的关键设计想要事前跨模型评审。
纯执行细节不找——能自己实测的自己测，别把另一个模型当搜索引擎。

**做法**：

1. 通道：**评审一份 diff 用 `xreview` skill**（外发规则已机制化：默认只发 diff、凭证永不发、设计文档与口令·权限类文件须用户授权并点名接收方、评审方拿不到仓库）。只是讨论方案、不发代码时，Claude Code 里可用 `mcp__codex__codex`（延迟工具，先 `ToolSearch` `select:mcp__codex__codex` 再调）——**同样的外发限制照样适用**：别把凭证、设计文档、权限配置贴进提问里；拿不准就先问用户。
2. 对方**不共享本会话上下文**：必须一次写清问题、约束（规格章节号 / 已有 D 编号 / 相关 `file:line`）、候选方案与各自代价，否则只会拿到泛泛之谈。
3. **拿到回复先自己实测复核再采信。** 先例：有项目实测修正了 Codex 的两处结论。**禁止把"某模型说"写进 Evidence 当依据——依据只能是实测结果。**
4. 落痕：属决策 → DECISIONS 追加一条（背景 / 决定 / 理由 / 影响）；属评审往返 → 存 `docs/reviews/{任务}_{模型}_{日期}.md` 并在 PLAN Evidence 引用。
5. 讨论完仍需用户拍板的 → 停下问。**另一个模型的意见不构成用户授权。**

## 逐任务循环与交接（模式一 / 二 / 三）

用户说"继续 / 下一个任务"时，回到【定位任务】做下一个未勾任务。每个任务收尾都已输出进度块；然后：

- **同会话续跑**：刚做完轻型/常规任务，且没命中「什么时候提清场」的信号。
- **停下等确认**：刚做完【单独+确认】命门任务（批量授权不覆盖命门确认门）。
- **清场交接**：刚做完【重型】任务，或命中「什么时候提清场」的信号 →「任务 M__-T__ 已提交。上下文偏重了，建议清场：`/kof c`。」然后走模式二清场阶段：清点 → 落盘 → clear → 重载补漏。代码与勾选在盘上，**只在对话里的东西靠清点**。
- **里程碑完成**：停下汇总交付内容，提示走 `close`。
- 不想逐个发话 → 用模式四（`/kof a`）：停下与交接的判据见其停止条件，规则同上，区别只是不等用户逐个发话。

## 常见借口 → 反驳

| 借口 | 反驳（都发生过） |
|---|---|
| "改动很小，布局断言不用跑" | 四命令全绿抓不到裁切：购买确认框金额被圆角裁掉时，lint / typecheck / build / test 全绿。 |
| "只跑 scrollWidth 那条就够了" | 祖先有 `overflow:hidden` 时它恒为 0——该断言被记"已归零"两次，实际顶栏一直溢出 42px。 |
| "函数没报错，应该成了" | 真实项目最高发的失败家族是"调用成功但什么都没发生"：空 `catch {}` 吞掉注册失败、`src?.setData()` 静默吞掉"图层从没建成"。验可观察结果。 |
| "测试红了，先把这条断言放宽 / 跳过，后面再补" | "后面"不会来。放宽断言让检查变绿 = 把红灯拔掉，不是修车。查根因；连修 3 次不过就停下报告。 |
| "顺手把旁边那个文件也修了" | 越 Writable Scope 的"顺手"是并行协作里互相覆盖的头号来源；记下来、建议，不动手。 |
| "这点偏差不值得写进 Evidence" | 用户只能通过进度块看到项目。不写 = 对用户隐瞒 = 收口门返工。 |
| "PLAN 有点乱，我重新整理生成一份" | PLAN 被整文件重写损坏过两次（丢任务、抹掉全部复选框）。只增量编辑。 |
| "这条教训上次已经记过文档了，这次再记一条" | 同一教训复发 ≥2 次，该改的是代码结构（收敛入口 / 反向枚举断言 / 签名强制），不是再写一段文字。 |
| "命令输出太长，接个 `\| tail` 看结尾" | 管道会吞退出码：lint 红着，`&&` 链照样往下提交推送。 |
| "状态都在 PLAN 和 git 里，直接 /clear 就行" | 在盘上的只有代码和勾选。用户说过的“不动 X”、做到哪一步、试过什么没成、在途的 PR——只在对话里；上下文被压缩时它们无声消失（手册仓库自己的会话丢过）。先清点再清。 |

## 危险信号

- 连续做了几个任务，一次进度块都没输出。
- Evidence 里从来没有出现过 `偏差：`——要么项目极其顺利，要么没如实写。
- 为了让端到端"能跑通"，手工补了一步用户不会做的操作。
- 想不起某条规则的出处，却准备照"一般最佳实践"做——先回去读 `CLAUDE.md`。
- 上下文里有一段压缩摘要，你却还在凭摘要里的细节做事——先清场。
- 用户说“我说过了”——那是一条没落盘的约定，先落盘。

## 踩坑的去向（坑位晋升机制）

项目自己踩的坑**不写在本 skill 里**，写进项目 `CLAUDE.md` 的「易错点」（现象 → 根因 → 规避动作，注明出处 M__-T__ / D__）。晋升路径：第一次踩 → 记进「易错点」；**同类第二次** → 升格为机制（permissions / hook / CI 闸门 / `ENGINEERING.md` 的禁令）；第三次 → 改代码结构使违规需要绕路（手册护栏 12）。文档是记录，机制才是拦截。

跨项目通用的环境类坑（Claude Code 工作环境本身的）：

- **组件库下拉（AntD Select 类）在自动化里点不动是常态** → 用 form_input 展开后对 option 元素 dispatch mousedown/mouseup/click 完整事件串；仍不行则降级为验后端 API + store 逻辑。
- **预览沙箱会节流 WebGL 渲染**（地图矢量层可能不可视化）→ 用数据探查（querySourceFeatures / 网络请求）验证正确性，别据此判定代码 bug。
- **preview 起的子进程没有 shell 的代理环境变量** → 外呼行为与终端不同；验外部集成用独立脚本直连，UI 链路用真实响应回放。
- **本机到外部 API 的 TLS 握手不稳是常态** → 连续失败先用独立脚本多跑几轮定性链路，别当代码 bug。
