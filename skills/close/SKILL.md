# close · 里程碑收口验收门

> 收口是手册里步骤最多、最容易漏的一道门，也是"前几轮记成绿的东西"现形的地方——真实项目**每次**收口都真的抓到东西。本 skill 把它从 PLAN 模板里的一大段话变成一份逐步出证据的流程。
> 安装：复制到项目的 `.claude/skills/close/`（Codex：`.agents/skills/close/`）；同时把手册仓库的 `agents/security-auditor.md` 复制到 `.claude/agents/`。
> 项目的根命令、涉敏点、基准视口不写在这里：分别读 `ENGINEERING.md`「根命令」、`CLAUDE.md`、`AGENTS.md`「运行模式声明」。

**每一步的产出都是证据（命令输出 / 截图 / 文件:行），不是"已检查"三个字。任何一步不过 → 停下报告，不往后走。**

## 流程

### 0 · 前置核对

- 跑 `prog --full`（收口要看全量：偏差全文、其他在途、挂账、git 与 CI 健康）：本里程碑除收口任务外全勾；工作区干净。
- **`待拍板：` 必须清零**（逐条请用户裁决）。**`偏差：` 逐条三选一**：现在修 / 延后（记 DECISIONS 伏笔四要素：延后什么、归属哪个里程碑、当前怎么占位、为什么）/ 用户明确接受。裁决后按约定改写标记（`已拍板（D××）：` / `偏差（已处理）：`）。

### 1 · 四根命令

从仓库根逐条跑 `ENGINEERING.md` 的 lint / typecheck / build / test。**不接管道**（`| tail` 会吞退出码，红着也显示通过）。本里程碑改过构建 / 依赖 / 生成步骤的，先本地模拟 CI（清 dist 与缓存 + 无 `.env`，按 CI 步骤顺序）。

### 2 · 重跑全部历史断言（不只本轮增量）

- 布局双断言，**两条一起跑**：`scrollWidth - clientWidth === 0` + 最右元素 `getBoundingClientRect().right` ≤ 容器右缘；登录成真实角色、带最宽真实数据、在项目声明的基准视口。
- 防线类断言先确认"它能失败"：构造应当被拦的场景，看它红一次。
- 以前里程碑记过"已通过"的断言，这里**重新实测**，不引用旧结论。

### 3 · 端到端实证 DoD + 旅程走查（手册阶段 3.5）

以新用户身份，从入口把本里程碑该通的旅程**整条**走一遍（网页项目用浏览器工具；触发方式必须与用户真实操作一致——为了"能跑通"而人为补的步骤本身就是缺陷信号）。每一步问：我知道现在能干什么吗？下一步入口清楚吗？和上一步接得上吗？结束态：我完成了想做的事、看到了结果吗？主要页面的空 / 错误 / 加载态真的触发得到吗？

再逐条问**能力可达性**：本里程碑交付的每个能力，从 UI 起点有没有一条真实的写入 / 触达路径？（两端测试全绿 ≠ 能力可达。）

产出「旅程走查记录」，缺口按 **断路 > 信息缺失 > 打磨** 排序。**断路必须在本里程碑补完**；其余记 DECISIONS 或下一里程碑任务。

### 4 · 涉敏里程碑：独立 A5 审计

本里程碑碰到 鉴权 / 支付 / PII / 文件上传 / 用户输入入库 任意一项 → 必做：

1. 调用 **`security-auditor` 子代理**（不支持子代理的工具：开新会话跑同一份提示词）。给它基线 commit、涉敏点、隔离 worktree 与隔离测试库。**禁止在本会话里自审。**
2. 高危逐条修复后，**让同一个审计代理用原手法复测整条攻击链**，不是"代码看起来修了"。
   - **复测之后又改了代码（第二轮修复、顺手加固）→ 这批改动同样要交回审计代理复测**，直到"最后一次改动之后有一次复测"为止——不然最后落进 main 的，恰好是没人审过的那一版。确实不再复测的（改动极小、与安全面无关），写一条 `偏差：` 说明改了什么、为什么不复测、拿什么自证，留给用户在第 6 步裁决。
   - 当轮修掉的中低危，至少由审计代理对修复点做一次定点复验；不要只在实现会话里自己确认。
3. 中低危处置：本轮引入且修法极小 → 当轮修；涉及对用户的不实承诺 → 当轮修；需要设计反转或部署决策 → 显式挂账记 DECISIONS，下个涉敏收口重新裁决。
4. **高危清零**才能继续。报告的「未覆盖面」转入 DEPLOY 检查单或 backlog。

### 5 · 文档同步与归档（与收口改动同一个 commit）

- `CHANGELOG.md` 顶部追加 `0.{n}.0`：至少一行"新用户现在能完成什么"；项目有版本号文件的（`package.json` / `pyproject.toml` / `__init__` 等）同步 bump，版本号处处一致。
- 有子系统参考文档的：同步 `{DOMAIN}.md` 并更新「最后同步」戳。
- 核对 DECISIONS 里**归属本里程碑**的伏笔是否都已兑现。
- 本里程碑任务清单**整段剪切**移入 `PLAN-ARCHIVE.md`，PLAN 留一行指针并把 `当前里程碑` 切到下一个。只移不删、不重排、不重生成；改完 `git diff` 核对：PLAN 减少的复选框数 = ARCHIVE 增加的复选框数。

### 6 · PR 与 CI —— 然后停下

推分支、开 PR，贴出 `gh pr checks` 的结果。红 → 先修；job 秒级失败（<60s）先查 check-run 注解与 runner / 磁盘，别当代码问题 rerun（修了 ci.yml 必须触发**新 run**，rerun 复用旧快照）。

**停下，交给用户两件事**：① 亲自走一遍旅程——"像不像一个产品"这层判断不能由 AI 代替；② 合并 PR。未经用户明确授权，不替用户合并。

### 7 · 合并后核对

- `git log origin/main`：本里程碑**全部** commit 已进 main（首次合并后追加的 commit 要再开 PR）。
- `gh run list --branch main --limit 1`：main 自身 CI 为 success；红着不准开下一里程碑。
- 删除已合并分支：本地 `git branch -d`；远程分支删除前向用户确认。

### 输出：收口报告

```
里程碑 M{x} 收口报告
DoD 实证：{做了什么操作、看到什么结果}
四命令：{逐条结果}      历史断言重跑：{条数 / 新抓到的问题}
旅程走查：断路 {n}（已补 {n}）· 信息缺失 {n} · 打磨 {n} → 去向
A5：{不涉敏 / 高危 0、中 {n}、低 {n}；未覆盖面 → 去向}
偏差裁决：{逐条去向}
文档：CHANGELOG {版本} · PLAN 归档复选框 {a} = {b} · {DOMAIN}.md 同步戳
PR：{链接} · CI：{gh pr checks 原文}
等你：① 亲自走一遍旅程 ② 合并 PR
```

## 常见借口 → 反驳

| 借口 | 反驳（都发生过） |
|---|---|
| "任务全勾、四命令全绿，走查可以省" | 每个零件都对 ≠ 产品能用：有项目攒到 M7 才发现"像 demo"；有能力两端测试全绿，但表里 0 行且**没有任何写入路径**——生产里它永远搜不到东西。 |
| "上个里程碑验过的断言不用重跑" | 布局断言被记"已归零"两次，收口实测顶栏溢出 42px、用户菜单被裁半截——从上个里程碑起就没真正过。 |
| "A5 我顺手审一下更快" | 自己验自己的新控制不可信：8 轮审计里，每轮唯一名不副实的防线恰好都是本轮自己新加的。 |
| "高危修完了，diff 看起来对" | 第一轮修复常只把攻击链挪一步：修完复验又抓到 `GRANT ON ALL TABLES` 把刚建的防护表授了回去。 |
| "复测已经过了，后面这点小改不用再审" | 复测通过的是**复测时**的代码。首次真实试用（TideAnywhere M12）就出现了"复测后的第二轮修复没再交审计"——当时靠会话如实写了一条偏差、用户才知道；规则不该指望每次都有人这么自觉。 |
| "红的那个 check 是无关的 flaky，先合" | 曾有 main 连续四个里程碑带红合并没人发现——本地总绿，是 dist / `.env` 残留掩盖了 CI 的真实状态。 |
| "归档时顺便把 PLAN 整理一下" | PLAN 被整文件重写损坏过两次。归档只做剪切移动。 |
| "这个偏差先挂着，以后再说" | 可以延后，但必须落成 DECISIONS 条目并标归属；不留痕的"以后"到时没人记得它存在。 |

## 危险信号

- 走查记录全是"通过"、一条缺口都没有 → 多半没真走。
- 为了让旅程走通，手工补了一步用户不会做的操作（手动 `focus()` 再 `blur()` 之类）。
- 审计报告没有「未覆盖面」一段。
- 想用 `gh run rerun` 解决刚改过 workflow 的失败。
- 还没贴 `gh pr checks` 就说"可以合并"。

## 验证

收口报告各栏都有可复核的证据；`gh pr checks` 原文在；PLAN / ARCHIVE 复选框数对得上；A5（如涉敏）有审计报告与复验报告两份。
