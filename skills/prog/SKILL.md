# prog · 项目进度块

> 解决的问题：用户不停点"下一步"，项目状态却是黑箱。本 skill **只读、不改任何文件、不加载规则文档**，任何会话随时可调，成本约等于一条命令。
> 安装：整个目录复制到项目的 `.claude/skills/prog/`（Codex：`.agents/skills/prog/`）。脚本也可以不经 AI 直接跑：`bash .claude/skills/prog/prog.sh`（建议挂成 `make progress`）。

## 流程

1. 从仓库根运行本目录下的脚本，**原样**贴出它的输出（放进代码块，不改写、不重排、不四舍五入）：

   ```
   bash <本 skill 目录>/prog.sh            # 默认精简三段，读 ./PLAN.md
   bash <本 skill 目录>/prog.sh --full     # 全量（收口、排查时）
   bash <本 skill 目录>/prog.sh path/to/PLAN.md
   ```

2. 在输出下面最多补 **两行**脚本不可能知道的事：本会话正在做、尚未落盘的东西（如"T6 写到一半，测试未跑"），或脚本报错的原因。没有就不补。
3. 不做别的。不顺手开始下一个任务，不顺手修"待你处理"里的条目——那些是留给用户的。

## 进度块怎么读

**默认只有三段**（试用反馈：全量信息太多，用户每个任务收尾真正要看的只有这些）：

```
项目     ███████████████░ 12/13 个里程碑已收口（总体 93%）
当前     M12「导入读取设界与 M11 A5 欠账清零」 1/5 个任务
下一步   M12-T2 · 读取器 / 导入器补测 【轻型】【可批量】  （不需要你）
待处理   ① T1 偏差：越 Writable Scope 改了 tests/test_input_seal.py…
```

| 段 | 含义 | 数据来源 |
|---|---|---|
| 项目 / 当前 | **项目总体进度**：已收口里程碑数 / 里程碑总数；已收口 = 标题标了 `已收口` 或 ✅ 的 ∪ `已完成里程碑：M0–M11` 那行列出的（归档后 PLAN 可能已不留它们的标题）；总体百分比把当前里程碑的任务完成比例也折进去，所以每勾一个任务都会动。**当前** = 当前里程碑的 已勾/总任务数；当前里程碑取 `当前里程碑：` 声明的那个，没声明或它已收口就取第一个还有未勾任务的未收口里程碑 | 里程碑标题、`已完成里程碑：` 行、任务行 |
| 下一步 | 第一个未勾任务 + 它要不要用户：挂着未处理的 `待拍板：` = **卡在用户这里**；**收口**任务 = 走 `close`、需要用户到场；带 **命门 / 单独** 标 = 做完会停下等核验；带 **重型** 标 = 先出计划等确认；都没有 = 不需要用户。标题过长只截描述、保留【…】标注 | 任务标题上的标注 |
| 待处理 | 当前里程碑里未处理的标记行。`待拍板：` 要用户马上决定 → **全文**；`偏差：` 到收口才裁决 → 只给一行（全文看 `--full` 或 PLAN） | 任务块内以这两个词开头的行 |
| ⚠ 警告 | 只在 main 的 CI 不是 success / 进行中时才出现 | gh |

**`--full`** 在三段之外追加：全局状态计数与 `已完成里程碑：` 原文、【涉敏】提示、最近勾选、距收口（剩余任务顺序）、其他在途里程碑、挂账（已收口里程碑下仍未勾的 EXT-/SEC- 类条目）、git 与 CI 健康、最近提交；`偏差：` 为全文。**收口时用 `--full`**，平时用默认。

## 脚本认得的 PLAN 写法（取自 5 个真实项目，不是只认模板）

- 里程碑标题：`## M3 · 名称`；id 可以是 `M-PROD1`、`M-v1.2` 这类；允许 `## 某前缀：M-PROD1 · 名称`；标题里有 `已收口` 或 ✅ 视为已收口，有【涉敏】会提示收口要过 A5。
- 任务两种写法都认：顶格复选框 `- [ ] **M3-T4 · 名称** —【重型】【单独+确认】`（缩进的子复选框不计）；表格行 `| M30-T1 | 内容 | ✅ |`（状态列 ✅ = 完成，其余 = 未完成）。任务号可以是 `M2-T11a1`、`EXT-1`、`M11-P1`。
- 不在 `## M…` 标题下的复选框一律不计。

## 「待你处理」标记约定（写 Evidence 的人要遵守）

任务收尾回填 Evidence 时，需要用户知道的事单独起一行，用固定词开头：

- `待拍板：{需要用户做的决定}` —— 会让 `/kof a` 自动循环**停下**。
- `偏差：{与完成定义不一致的地方 / 没测到的范围 / 临时绕过}` —— 不停，但一直挂在进度块里，直到收口门统一裁决。
- **标记行只写一句话**（是什么 + 影响到哪）；来龙去脉、根因、怎么修的写在 Evidence 正文里。标记行是给用户一眼扫的，写成一段话等于没写。

处理完后把开头改成 `已拍板（D××）：…` / `偏差（已处理）：…`，它就从进度块消失；原文保留作证据。

## 常见借口 → 反驳

| 借口 | 反驳 |
|---|---|
| "我记得做到哪了，直接说就行" | 进度块存在的理由就是不信记忆。手册护栏 11：布局断言被"记成已归零"两次，实际从上个里程碑起就没过。口述的"大概完成 60%"是同一种假绿。 |
| "脚本输出太啰嗦，我总结一下" | 总结 = 重新引入模型转述。用户要的是能对账的原始数字；想补充就写在输出下面的两行里。 |
| "这个偏差很小，不值得写 `偏差：`" | 用户看不到的偏差，就是收口时的意外。写一行的成本远低于收口门返工。 |
| "PLAN 的勾选状态和实际不符，我按实际报" | 那是 PLAN 错了：先报告不一致、改对 PLAN（增量编辑），再跑脚本。不要让进度块和 PLAN 各说各话。 |

## 危险信号

- 输出里的数字和 PLAN.md 里数出来的不一样 → 脚本或 PLAN 格式有问题，先跑 `prog.sh --selftest`，别手工"修正"数字。
- "待你处理"越积越多却没人看 → 用户没在看进度块；在下一个停点主动念出来。
- 脚本报"没有找到里程碑标题"或任务数明显偏少 → PLAN 的写法超出了上面认得的范围；优先把 PLAN 改回认得的写法，确属合理的新写法再改脚本并补一条夹具。

## 验证

- `bash prog.sh --selftest` 输出 `selftest ok`（自带三份夹具：复选框与表格两种任务写法、前缀标题、`M3-T4a1` 式任务号、已收口里程碑下的挂账、全部收口的 PLAN、收口任务提示；并断言已处理条目、缩进子复选框、非里程碑标题都不被计入）。
- 贴出的进度块与脚本输出逐字一致。
