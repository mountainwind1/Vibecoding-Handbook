# xreview · 异构模型复核门

> 不同厂商的模型盲区不同：实现方自己查不出的问题，换一家常常一眼看到。但对方是**顾问不是裁判**——它看不到仓库、没有运行环境，所有发现都只是「读码推断」。
> 安装：整个目录复制到项目的 `.claude/skills/xreview/`（Codex：`.agents/skills/xreview/`）。只用 Python 标准库。
> key 只从环境变量取：`DEEPSEEK_API_KEY`、`GLM_API_KEY`（或 `ZHIPUAI_API_KEY`），由用户自己设在 shell 配置里；**任何时候不读、不打印、不写入它们的值**。缺 key 的评审方自动跳过。Codex 用本机已登录的 `codex` CLI。
> 模型名不用配置：脚本内置各家当前的旗舰档（`deepseek-v4-pro`、`glm-5.3`，2026-09 对照官方文档核实）；厂商换代后改脚本里 `HTTP_VENDORS` 一处，或临时用环境变量 `XREVIEW_DEEPSEEK_MODEL` / `XREVIEW_GLM_MODEL` 覆盖（想省钱可设成 `deepseek-flash` / `glm-5.3-flash`）。

## 外发规则（机制化，不靠自觉）

| 内容 | 规则 |
|---|---|
| 被评审的代码 diff | 默认就发这个，别的都不发 |
| **凭证文件**：`.env*`、私钥（`*.pem` / `*.key` / `id_rsa*`）、`auth.json`、`.netrc`、`*.tfstate` … | **永不外发，没有授权开关**。出现在 diff 里即拒发（用 `--exclude` 去掉）；发出前再用 gitleaks 扫内容，运行异常也拒发 |
| **需授权内容**：全局设计文档（`PRD*` / `DESIGN*` / `DECISIONS*` / `doc/` `docs/` / 名字含 设计·架构）、名字涉及口令或权限的文件（`*password*` `*secret*` `*credential*` `*permission*` `*权限*` …） | **默认自动扣下**并列出，评审照常进行。要发：**先停下问用户** → 拿到明确同意后带 `--include-restricted --authorized "<谁、何时、同意把什么发给谁>" --authorized-for <接收方>`——授权点名发给谁就只发给谁 |
| 额外附带文件 / 整份文件（`--include` / `--payload`，如把 PRD 送审） | 同上：必须授权并点名接收方；符号链接不跟随 |
| 项目自己的禁区 | 写在项目 `ENGINEERING.md`「外发限制」里，调用时用 `--withhold <glob>` 逐条带上 |

评审方**拿不到仓库**：Codex 在只含评审包的目录里、用权限档隔离运行，且每次先跑一条零成本预检（正对照：评审包读得到；负对照：仓库文件读不到——读得到就拒跑）；DeepSeek / GLM 直连 HTTPS API（只允许厂商域名，不跟随重定向），没有代理外壳也就没有读文件的能力。
已知边界：Codex 权限档的最小可读集包含系统临时目录，**别在 `/tmp` 放敏感内容**；权限档是 beta，所以预检不能省。

## 流程

1. **先 dry-run 看会发什么**（什么都不发）：
   ```
   python3 <本 skill 目录>/xreview.py --base main --task M3-T4 --dry-run
   ```
   看三行：包含哪些文件、扣下了哪些、密钥扫描是否通过。被扣下的文件如果正是这次评审的重点 → 停下问用户要不要授权，**不要自己决定**。
2. **正式跑**（评审方按需选；`--focus` 写一句这次最该看的面）：
   ```
   python3 <本 skill 目录>/xreview.py --base main --task M3-T4 --reviewers codex,deepseek,glm --focus "并发写路径与失败降级"
   ```
   报告落在 `docs/reviews/{任务}_{评审方}_{日期}.md`（项目用别的目录就传 `--out`），头部记着评审包哈希、包含 / 扣下的文件、授权记录。
3. **合并裁决**（主控模型做，这一步才是价值所在）：
   - 把各家发现按「文件:行 + 问题」归并；**多方同报 = 大概率真问题，优先处理；只有一方报 = 先复现再动**。
   - 每条要采信的发现，先**写成会失败的测试或最小复现**，确认它真的成立，再修——对方是读码推断，编造行号、误读上下文都发生过。
   - 不成立的也记一句为什么不成立，免得下次重查。
   - 各家的「未覆盖面」汇总进收口报告的未覆盖面。
4. **落痕**：采信并修复的写进任务 Evidence（依据写**你的复现结果**，不写"某模型说"）；涉及取舍的记 DECISIONS。报告文件随任务 commit 一起提交。

## 什么时候用（按档位，不是每个任务都用）

| 场景 | 用法 |
|---|---|
| 【重型】/ 命门任务的 diff，合并前 | 1–2 个异构评审方；`--focus` 指向该命门的失败形态 |
| 涉敏里程碑收口 | 在 `security-auditor` 子代理之外再加一层异构视角（不替代它——子代理能实测，xreview 不能） |
| 上游产物（PRD / 契约 / PLAN / 迁移）送审 | 价值最高，但属**需授权内容**：先问用户，再 `--payload PRD.md --authorized … --authorized-for codex` |
| 常规 / 轻型任务 | 不用。两个模型审一个轻型任务，花的比省的多 |

## 常见借口 → 反驳

| 借口 | 反驳 |
|---|---|
| "它自己说读不到仓库外的文件，隔离没问题" | 实测过：Codex 在默认只读沙箱里**自称**读不到目录外，实际 `cat` 任意仓库文件都成功。模型的自述不是证据，预检才是。 |
| "用户上次同意过把 PRD 给 Codex，这次也一样" | 授权是一次一议、点名接收方的。上次给 Codex ≠ 这次给 DeepSeek，也 ≠ 这次的另一份文档。 |
| "三家都说没问题，可以合了" | 它们看到的只是 diff，没有运行环境，扣下的文件也没看。"未发现问题"不是"没有问题"；四命令、历史断言、旅程走查一样都不能少。 |
| "Codex 指出的问题看着很对，直接改" | 先复现。本 skill 自己的脚本被 Codex 审出 7 条，逐条先写成失败用例确认成立才修——也正因为写了用例，才发现其中一条修法还留着漏网变异。 |
| "被扣下的就是要审的重点，我把它改个名字发" | 重命名、符号链接、大小写、八进制转义的路径都已堵上；更重要的是——绕过外发限制不是你能替用户做的决定。 |

## 危险信号

- 预检显示"隔离预检失败" → Codex 的权限档写法可能变了。**不要**改成用 `-s read-only` 凑合跑（那个挡写不挡读）。
- 想把 key 写进命令行、脚本或仓库文件 → 停。key 只存在于用户的环境变量里。
- 报告里的行号在 diff 里对不上 → 对方在编，整份报告降低信任。
- 发现自己在转述"DeepSeek 认为…"作为修改理由 → 依据只能是你自己的复现。

## 验证

- `python3 xreview.py --selftest` 输出 `selftest ok`（路径分类两档、重命名 / 符号链接 / 大小写 / 八进制转义路径、授权须点名接收方、密钥扫描、接口地址白名单、HTTP 请求形态、缺 key 跳过、隔离预检不得空过）。
- 每份报告头部有评审包哈希与授权记录；采信的每条发现在 Evidence 里有对应的复现证据。
